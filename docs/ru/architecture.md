# Архитектура

Deimos — панель управления обходом DPI. Он не правит пакеты сам: он управляет
[zapret](https://github.com/bol-van/zapret), которому принадлежит фактическая логика
десинхронизации.

```
                    +-------------------------------------------+
                    |              deimos (client)              |
                    |  CLI  ----------+                         |
                    |  GUI  ----------+--> DaemonClient (HTTP)  |
                    +---------------------------|---------------+
                                                | JSON over HTTP
                                   +------------v-------------+
                                   |          deimosd         |
                                   |  API server              |
                                   |  ConfigStore             |
                                   |  RuntimeEngine           |
                                   |    Process --> winws     |
                                   |               nfqws      |
                                   |               tpws       |
                                   +--------------------------+
```

## Компоненты

| Компонент | Цель | Ответственность |
| --- | --- | --- |
| `deimos_core` | статическая библиотека | Модель конфигурации, модель стратегий zapret и генерация команд, транспорт HTTP, клиент демона, супервизор процессов, каталог сообщений |
| `deimos_daemon` | статическая библиотека | Движок времени выполнения, хранилище конфигурации, REST API, интеграция со службами платформы |
| `deimosd` | исполняемый файл | Точка входа демона |
| `deimos` | исполняемый файл | Единственный клиентский бинарник: GUI по умолчанию без аргументов, CLI с аргументами |
| `deimos_tests` | исполняемый файл | Набор тестов Catch2 |

Всё общее живёт в `deimos_core`, поэтому CLI и GUI используют ровно один и тот же протокол,
разбор конфигурации и эндпоинты. Дублирования логики между двумя фронтендами нет — это две
подачи одного бинарника.

## Один бинарник, два режима

`deimos` — исполняемый файл с консольной подсистемой. Это сохраняет корректными конвейеры,
коды возврата и блокирующее поведение для скриптов: `deimos status --json | ConvertFrom-Json`
работает.

Выбор режима в `src/client/main.cpp`:

| Вызов | Результат |
| --- | --- |
| `deimos status`, `deimos --help`, любой аргумент | CLI |
| `deimos --gui` | GUI, всегда |
| `deimos` без аргументов из терминала | CLI, печатает справку |
| `deimos` без аргументов из Explorer или ярлыка на рабочем столе | GUI |

Проверка терминала использует `GetConsoleProcessList` в Windows (консоль, общая с
родительской оболочкой, означает «запущено из терминала») и `isatty` в остальных системах.
Перед открытием окна процесс вызывает `FreeConsole()`, поэтому двойной щелчок не оставляет
лишнего консольного окна.

## Поток конфигурации

1. `deimosd` загружает `<config>/deimos.json` (значения по умолчанию записываются при первом
   запуске).
2. Каждый профиль проверяется; диагностика возвращается клиентам вместо молчаливого
   отбрасывания недопустимых правил.
3. `PUT /api/v1/config` или запись профиля обновляет файл атомарно (временный файл плюс
   переименование), после чего демон заново находит zapret и перезапускает движок, если тот
   работал.

Схема версионирована (`schemaVersion`). Демон отвергает конфигурацию, записанную более новой
схемой, вместо того чтобы угадывать.

## Движок

`RuntimeEngine` владеет дочерними процессами zapret для одного активного профиля:

- `Profile` -> список `LaunchSpec` через `buildLaunches()`.
  `winws` получает единственный процесс с разделителями `--new` между раундами, потому что
  именно так инструмент zapret для Windows мультиплексирует наборы правил. `nfqws` и `tpws`
  принимают один набор правил за вызов, поэтому Deimos запускает по процессу на раунд с
  инкрементированным `--qnum`.
- Каждый процесс запускается с перехваченными stdout/stderr. Строки передаются в журнал под
  `zapret/<profile>` и в буфер неполной строки для каждого процесса, поэтому фрагмент,
  разорванный посередине строки, никогда не обрезается в журнале.
- Поток монитора опрашивает дочерние процессы (`Process::poll()`), применяет политику
  перезапуска из `engine.maxRestarts` / `engine.restartBackoffMs` и переводит движок в
  состояние `faulted` с `lastError`, когда перезапуски исчерпаны или отключены.
- В Windows дочерние процессы помещаются в job object с `KILL_ON_JOB_CLOSE`, поэтому они
  никогда не переживают упавший демон. В POSIX каждый дочерний процесс получает свою группу
  процессов, принимает `SIGTERM`, а после льготного периода — `SIGKILL`.

## Потоки

| Поток | Чем владеет |
| --- | --- |
| Рабочие потоки API-сервера (пул cpp-httplib) | Обработка запросов; всё общее состояние защищено мьютексами `ConfigStore` и `RuntimeEngine` |
| Монитор движка | Обнаружение завершения дочерних процессов и перезапуски |
| Потоки чтения процессов (по одному на каждый поток вывода) | Вычитывание stdout/stderr в журнал |
| Поток опроса GUI | Периодический запрос состояния, профилей и журналов |
| Рабочий поток GUI | Сериализованные действия (запуск/остановка/сохранение/удаление), чтобы UI никогда не блокировался на сети |

Движок использует два мьютекса: `mutex_` для состояния и `outputMutex_` для буферов неполных
строк. Обратные вызовы вывода никогда не берут мьютекс состояния — именно поэтому остановка
процесса, когда его поток чтения находится посреди записи, безопасна.

## Модель безопасности

- По умолчанию демон слушает `127.0.0.1`. Прослушивание любого другого адреса требует
  одновременно `allowRemoteClients` и `requireAuthentication`; иначе конфигурация
  отвергается.
- Каждый эндпоинт, кроме `/api/v1/health`, требует `Authorization: Bearer <token>`, когда
  аутентификация включена. Сравнение выполняется за постоянное время.
- Токен лежит в `<state>/token` с правами только для владельца и печатается один раз командой
  `deimosd --generate-token`.
- TLS (`enableTls` плюс сертификат и ключ) необязателен и включается при сборке флагом
  `-DDEIMOS_ENABLE_TLS=ON`. Для развёртываний, смотрящих в интернет, ставьте демон за
  обратный прокси или SSH-туннель, а не выставляйте его напрямую.
- Самому zapret нужен прямой доступ к пакетам: запускайте демон как службу с
  `CAP_NET_ADMIN`/`CAP_NET_RAW` или устанавливайте службу Windows из командной строки с
  повышенными правами.

## Язык и диагностика

Каждое сообщение, которое производит демон — диагностика валидации, тела ошибок API и его
собственные строки журнала, — переведено. Язык берётся из `--lang`, `daemon.language` или
языка интерфейса системы; см. [Локализация](./localization.md). Каталог находится в
`src/core/support/i18n_catalog.inc` и компилируется в оба бинарника, поэтому демон на
роутере и клиент на настольной машине делят одни и те же строки без поставки файлов данных.

Клиент держит свой язык: русский `deimos`, работающий с английским `deimosd`, рисует
интерфейс по-русски и показывает сообщения демона по-английски. Задайте `daemon.language` на
демоне, если нужен единый язык по всей цепочке.

## Почему бы не линковаться с zapret?

zapret — набор автономных инструментов со стабильной командной строкой и без встраиваемого
библиотечного API. Deimos считает их внешней зависимостью: те же бинарники, которым
пользователь уже доверяет, без патчей, без вендоринга, а точные команды видны через
`GET /api/v1/profiles/{id}/preview` до того, как что-либо запущено.
