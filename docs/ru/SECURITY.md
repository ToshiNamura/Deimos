# Политика безопасности

## Поддерживаемые версии

| Версия | Поддерживается |
| --- | --- |
| 0.1.x | да |

Исправления получает только последний релиз.

## Сообщение об уязвимости

Используйте приватное сообщение об уязвимостях GitHub: откройте вкладку **Security** в
[ToshiNamura/Deimos](https://github.com/ToshiNamura/Deimos/security) и выберите
**Report a vulnerability**. Не открывайте публичную issue.

Пожалуйста, приложите всё, что можете, не вставляя действующие секреты:

- версии, которые выводят `deimosd --version` и `deimos --version`;
- платформу и способ запуска демона (запуск в переднем плане, служба Windows, systemd,
  launchd, контейнер);
- затронутый эндпоинт или команду;
- минимальное воспроизведение и, если есть, предложенное исправление.

Никогда не включайте bearer-токены, токены из `<state>/token`, закрытые ключи TLS или
приватные имена хостов. Достаточно отредактированной конфигурации.

## Область действия

В области действия:

- аутентификация и авторизация API демона: сравнение токенов, права доступа к хранилищу
  токенов, эндпоинты, доступные без токена;
- удалённый доступ: применение `allowRemoteClients` и `requireAuthentication`, настройка
  TLS;
- инъекции в сгенерированную командную строку zapret (поля профиля, списки хостов, пути,
  `extraArguments`) или в сгенерированный unit systemd и plist launchd;
- управление процессами: выход за пределы объекта заданий Windows или группы процессов
  POSIX, дочерние процессы, переживающие остановку демона, работа с привилегиями;
- отказ в обслуживании через HTTP-сервер (размер запроса, медленные клиенты,
  неограниченный рост логов) или через записи конфигурации.

Вне области действия:

- уязвимости в zapret, WinDivert или операционной системе; сообщайте о них
  разработчикам этих проектов;
- демон, намеренно выставленный в интернет без терминации TLS или с токеном, читаемым
  всем миром;
- проблемы, требующие уже скомпрометированного хоста или прав администратора/root.

## Усиление защиты

Эти свойства являются частью дизайна и покрыты тестами или проверками конфигурации:

- демон слушает `127.0.0.1`; любой другой адрес требует `allowRemoteClients: true` и
  `requireAuthentication: true`, иначе конфигурация отклоняется;
- каждый эндпоинт, кроме `/api/v1/health`, требует `Authorization: Bearer <token>`,
  сравниваемого за постоянное время;
- `deimosd --generate-token` записывает токен с правами только для владельца и выводит
  его один раз;
- TLS необязателен (`-DDEIMOS_ENABLE_TLS=ON`); для чего-либо за пределами доверенной сети
  терминируйте TLS в обратном прокси или используйте SSH-туннель, как описано в
  [docs/ru/deployment.md](./deployment.md).

## Раскрытие информации

Исправления поставляются с записью в `CHANGELOG.md`. По отчётам, поступившим через
приватное сообщение, публикуется GitHub security advisory с указанием автора отчёта,
если он не предпочитает иное.
