# Участие в разработке Deimos

Спасибо, что нашли время улучшить Deimos. Эта страница описывает, как проект
собирается, тестируется и оформляется, чтобы изменение можно было принять без лишней
переписки.

## Прежде чем начать

- **Отчёты об ошибках** приветствуются в виде issue. Укажите воспроизведение, лог
  демона и вашу платформу, как просит форма issue.
- **Крупные возможности** (новое поле профиля, изменение конфигурации, изменение API)
  стоит сначала обсудить в issue: они одновременно затрагивают схему, документацию API
  и клиент.
- **Проблемы безопасности** решаются через [SECURITY.md](./SECURITY.md), никогда в
  публичной issue.

## Требования

| Требование | Примечания |
| --- | --- |
| CMake 3.25 или новее | пресетам Ninja также нужны Ninja и оболочка разработчика |
| Компилятор C++20 | MSVC 19.4x (Visual Studio 2022/2026), GCC 12+, Clang 15+ |
| Зависимости GUI в Linux | `libgl1-mesa-dev libx11-dev libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev`, либо настройка с `-DDEIMOS_BUILD_UI=OFF` |
| zapret | нужен только для работы с реальным трафиком; набор тестов использует `deimos_fake_zapret` |

nlohmann/json, cpp-httplib, Catch2, GLFW и Dear ImGui скачиваются через FetchContent при
первой настройке. Передайте `-DDEIMOS_FETCH_DEPS=OFF`, чтобы вместо этого использовать
системные пакеты.

## Сборка и тестирование

Пресеты Ninja рассчитаны на оболочку разработчика (`vcvars64.bat` в Windows, обычную
оболочку с компилятором в Linux и macOS). Для каждой платформы есть своя пара пресетов,
и они настраиваются только на своём хосте:

```bash
cmake --preset linux-debug      # or x64-debug on Windows, macos-debug on macOS
cmake --build --preset linux-debug
ctest --preset linux-debug
```

Сборки попадают в `out/build/<preset>`, а установка — в `out/install/<preset>`.

`daemon-only` собирает только `deimosd` без UI, CLI и тестов:

```bash
cmake --preset daemon-only
cmake --build --preset daemon-only
```

Запуск одной области набора тестов выполняется по тегам Catch2:

```bash
./out/build/linux-debug/bin/deimos_tests "[zapret]"
```

Доступные теги — `[config]`, `[protocol]`, `[zapret]`, `[process]` и `[api]`.

## Тесты

- Добавляйте тесты для поведения, которое вы добавляете или исправляете, в существующий
  файл этой области: `tests/test_config.cpp`, `test_protocol.cpp`,
  `test_command_builder.cpp`, `test_process.cpp` или `test_api.cpp`.
- Имена тестов читаются как `subject_scenario_expected`, например
  `buildLaunches_TpwsMapsSplitAndDisorder`. Предпочитайте тесты, которые падают до
  изменения и проходят после него.
- `tests/fake_zapret.cpp` заменяет `winws`/`nfqws`; расширяйте его, когда нужно новое
  поведение процесса, вместо того чтобы подменять супервизор заглушкой.

## Стиль

Форматирование задано в [.clang-format](../../.clang-format) и [.editorconfig](../../.editorconfig):
скобки Allman, 4 пробела, 120 столбцов, LF, UTF-8, без завершающих пробелов.

- `PascalCase` для типов, `camelCase` для функций, методов, локальных переменных и
  полей, `UPPER_SNAKE_CASE` для констант.
- Аббревиатуры — это слова: `userId`, `httpClient`, никогда `userID` или `HTTPClient`.
  Логические значения читаются как предикаты: `isReady`, `hasPermission`.
- Никаких анонимных пространств имён; используйте `static` или именованное пространство
  имён `detail`.
- Запускайте `clang-format -i path/to/file.cpp` для файлов, которые вы меняете. Дерево
  ещё не отформатировано целиком с текущим профилем, поэтому не смешивайте
  переформатирование всего репозитория с функциональным изменением.
- Держите сборку без предупреждений: MSVC запускает `/W4`, GCC и Clang —
  `-Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion`, а CI собирает
  задание Linux с `-DDEIMOS_WARNINGS_AS_ERRORS=ON`.

## Коммиты и пул-реквесты

- Одно логическое изменение на коммит, повелительное наклонение в теме
  («Add tpws split fallback») и тело, объясняющее, зачем нужно изменение.
- Обновляйте [CHANGELOG.md](../../CHANGELOG.md) в разделе `[Unreleased]`, когда изменение
  заметно пользователям.
- Обновляйте `docs/`, когда меняется эндпоинт, параметр, поле профиля или шаг
  развёртывания.
- Открывайте пул-реквест по шаблону: что изменилось, какую issue он закрывает и точные
  команды, которыми вы это проверили.
- Оба задания CI, Linux и Windows, должны проходить.

## Структура проекта

| Путь | Содержимое |
| --- | --- |
| `include/deimos/` | публичные заголовки `deimos_core` |
| `src/core/` | модель, транспорт, сопоставление zapret, управление процессами |
| `src/daemon/` | движок, хранилище конфигурации, REST API, интеграция со службами |
| `src/client/` | точка входа `deimos`, клиент командной строки и интерфейс ImGui |
| `tests/` | набор тестов Catch2 и вспомогательная заглушка zapret |
| `cmake/` | параметры, зависимости, флаги компилятора, упаковка, сводка настройки |
| `docs/` | архитектура, API демона, стратегии, сборка, развёртывание |
